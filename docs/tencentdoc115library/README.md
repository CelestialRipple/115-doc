# 腾讯文档115媒体库

插件把腾讯文档在线表格中的 115 分享链接同步为 MoviePilot 可管理的本地媒体库。电影和电视剧都会在构建时通过公开分享接口匿名校验并展开文件列表，播放或下载时才使用账户 Cookie 取得临时直链。插件不执行播放前转存，也不需要115开放平台授权。

## 当前能力

- “发现工作表”只读取表结构，不读取任何资源行。
- 支持同时配置多个腾讯文档；工作表显示为“文档别名（工作表名）”，同名工作表也不会冲突。
- 可手动继续同步、重新扫描，也可点击“同步全部并生成”，在后台沿断点跑完全部已选工作表，再逐批识别、刮削并生成所有 pending 资源。
- 一键任务可安全停止；重新点击后从工作表检查点和 pending 队列继续，也可继续使用 Cron 自动同步/生成。
- 每次最多读取指定页数，腾讯文档分页与 SQLite 检查点在同一事务提交；异常退出后最多重做当前页。
- 每次最多生成指定数量的资源，未完成和失败资源保留状态，可继续或定向重试。
- 插件详情页分别显示 STRM 和元数据刮削进度、待处理/失败/前序阻断数量，以及当前资源所处的分享校验、媒体识别、STRM 生成或刮削阶段。
- “重试全部失败并生成”会把分享、生成和刮削失败资源重新排队，并按受保护批次连续重试一轮；再次失败会保留真实错误，不会无限重试。
- 可限制整个输出目录的占用，统计 STRM、NFO 和图片；达到上限后停止后续生成，不删除已有文件，剩余资源保留为 pending。
- 每张工作表可选择“电影”“剧集”或“混合”类型；混合表逐行读取类型列，含“剧集”的行按电视剧处理，其余行按电影处理。
- 可在配置页二次确认后执行“清空并重新开始”，清空插件 SQLite 状态及输出目录中的 STRM、NFO、图片和临时文件，保留其他非插件文件。
- 使用 MoviePilot 的媒体识别与刮削链生成 NFO、图片和 STRM，不依赖 Emby 在线刮削。
- 电影和电视剧都在构建前匿名校验并递归枚举 115 分享；错误访问码、失效分享或无视频资源会记为 `share_error`，不会为该次构建生成 STRM。
- 电影从分享中选择体积最大的主视频；电视剧会结合表格类型与完整文件路径识别 `S01E02`、`S01`、`Season 1`、`第一季`、`第2集/话`，并识别季目录中的纯数字集名。
- 整季单文件若文件名只有 `Sxx` 或“第x季”，以及季目录中的 ISO，会作为该季第 1 集生成 STRM，避免整个资源被遗漏。
- 枚举分享文件只调用 115 公开分享目录接口，不读取、发送或初始化账户 Cookie；播放和下载生成临时直链时才读取 Cookie。
- 115 请求串行限速，对临时错误指数退避重试；播放直链按资源、文件和播放器 User-Agent 缓存100分钟，避免 Infuse 的 Range、拖动和重连反复调用115接口；错误访问码、失效分享和限流会分别记录真实原因。
- 115 分享地址不限制域名；只要 HTTP(S) URL 的路径包含 `/s/分享码` 或 `/share/分享码` 即可识别，包括 `115cdn.com` 等备用域名。插件只提取分享码，目录请求仍发送到固定的 115 公开接口。
- 115 明确返回分享失效或访问码错误，以及无法提取分享码、分享中没有可播放视频时，资源会标记为“无效分享（不再重试）”；批量和单条重试接口都会跳过。修正文档链接后重新同步即可按新记录处理。限流、超时、接口无响应仍属于可重试的临时分享错误。
- 接入 MoviePilot 原生手动检索和下载：检索只查询插件 SQLite 本地镜像，默认只展示已经生成 STRM 的资源，不会现场请求腾讯文档或 115。
- 点击下载后由插件接管任务，按需生成 115 临时直链并下载到 MoviePilot 选择的下载目录；支持 `.part` 文件和 HTTP Range 断点续传，并向 MoviePilot 报告进度和完成状态。
- 播放入口带插件自动生成的随机密钥，115 Cookie、腾讯令牌和播放密钥不会写入源码或日志。
- 可选启用内置 Emby 直链网关；客户端连接网关后，本插件 STRM 的播放和 Emby 原生下载请求会重定向到115临时地址，视频数据不经过 NAS，其余 Emby 请求原样转发。
- 内置网关会为受管 STRM 强制 DirectPlay、提供通用 DirectStreamUrl，并关闭服务端转码；网关同时接管 `stream`、`universal`、`original` 和下载入口。ISO 的容器、协议和媒体流字段保持 Emby 原值，不做客户端专用伪造。

## 工作表分组

首次发现时所有工作表都保持关闭，避免意外初始化整份文档。默认分组建议如下：

| 工作表 | 默认输出分组 | 默认媒体类型 |
| --- | --- | --- |
| 电影大全、动画、纪录片、演唱会及其他 | 电影合集 | 电影 |
| 剧集 | 剧集 | 剧集 |
| 星火相关工作表 | 星火 | 混合 |
| 蚂蚁相关工作表 | 蚂蚁 | 电影 |

在插件配置页中，为不同工作表填写相同的“输出分组”即可合并；填写不同名称即可单独输出。非混合工作表必须明确选择“电影”或“剧集”。混合工作表会检查当前行的类型列：包含“剧集”（同时兼容电视剧、连续剧、TV、番剧）的行使用剧集刮削并写入“输出分组-剧集”，其他行使用电影刮削并写入基础输出分组。例如星火的电影写入 `星火`，剧集写入 `星火-剧集`。修改已同步工作表的分组或媒体类型后，插件会从该表开头重新同步，以便重新分类。

## 推荐的首次使用顺序

1. 配置一个或多个腾讯文档 URL、Client ID、Open ID、Access Token；要自动续期还需 Client Secret 和 Refresh Token。
2. 配置 STRM 输出目录，以及 Emby 可以访问的 MoviePilot 地址。Unraid 中不要填写 `127.0.0.1`，应填写 Emby 容器可访问的局域网或容器网络地址。
3. 保存后进入插件详情页，点击“发现工作表”。
4. 重新打开配置页，只启用要同步的工作表，并确认输出分组与媒体类型；星火这类电影、剧集共存的表选择“混合”。
5. 小规模测试可使用“继续同步”和“生成下一批”；确认配置后，点击“同步全部并生成”即可让后台自动跑完。需要抛弃当前检查点时才使用“重新扫描”。
6. 按 Unraid 可用空间设置“输出目录空间上限（GiB）”；`0` 表示不限。建议输出目录专用于本插件，统计才最直观。
7. 把输出目录分别映射给 MoviePilot 和 Emby，并在 Emby 中建立相应媒体库。

如果要彻底重新分类，在配置页先打开“我确认清空全部插件数据和生成元数据”并保存，再到插件详情页点击“清空并重新开始”。该操作会停止于后台任务运行时，且只删除插件输出根目录中的 STRM、NFO、常见图片和临时文件，然后清空 SQLite 与工作表配置记录；其他文件会保留。清空后重新“发现工作表”、选择类型并执行“同步全部并生成”。Emby 数据库不属于插件管理范围，需要在 Emby 中重新扫描媒体库以移除旧条目并发现新目录。

多个腾讯文档在配置框中每行填写一条，推荐使用“别名|链接”：

```text
电影库|https://docs.qq.com/sheet/xxxxxxxx
剧集库|https://docs.qq.com/sheet/yyyyyyyy
```

发现后会显示为“电影库（电影大全）”“剧集库（剧集大全）”。只填写链接也可以，插件会依次使用“文档1、文档2”作为别名。文档和工作表组合形成独立断点，因此不同文档中相同的工作表 ID 或名称不会互相覆盖。

## 批次与断点

- `每页行数` 同时受腾讯文档每次最多 1000 行和 10000 单元格限制。
- `每次最多页数` 控制一次同步的工作量，默认 5 页。
- `每次最多生成资源` 控制 MoviePilot 识别/刮削压力，默认 20 条。
- `输出目录空间上限（GiB）` 统计输出根目录中的 STRM、NFO 和图片。插件在每个资源开始前检查，单个资源生成完成时可能轻微超过上限。
- 一张表完成后会继续下一张未完成表；全部已选工作表完成后，下一次同步才开启新一轮扫描。
- 每条资源的分享展开以单条资源为恢复边界；进程中断时该条会重做，已完成资源不会重复构建。
- “同步全部并生成”仍按上述批次运行，只是自动连续提交下一批，因此不会一次把全部腾讯文档行载入内存。

## 115 与播放

插件优先复用“115网盘STRM助手”的 Cookie；也可以在本插件中单独配置。分享链接必须有效，访问码必须正确。若文档中的密码错误，插件会记录并返回访问码错误，不会伪装成网络故障。

电影和电视剧在生成 STRM 前都会递归枚举分享中的视频。这一步调用 `webapi.115.com/share/snap`，请求不带账户 Cookie；访问码仍必须正确，公开接口本身仍可能按 IP 限流，因此同样使用串行限速、重试和资源级断点。播放器请求电影或某一集 STRM 时，插件直接使用已经保存的文件 ID 生成临时地址，此时才使用账户 Cookie。插件不会把文件转存到个人网盘，也不会清理回收站。

## 内置 Emby 直链网关

启用内置网关后，客户端改为连接网关端口；网关识别本插件生成的 STRM，在播放或下载请求到达时直接返回115临时地址（307）。NAS 仍处理 Emby 登录、媒体库、封面和播放信息等小流量，不转发视频正文。网关不伪造 ISO 的容器、协议或媒体流信息，保持 Emby 原始媒体源字段，行为与 go-emby2openlist 的简单重定向方式一致。

插件配置：

- `启用直链网关`：开启后监听 `0.0.0.0` 的指定端口，默认 `8097`。
- `Emby 内部地址`：MoviePilot 容器能够访问的 Emby 地址，例如 `http://192.168.5.192:8096`。
- `Emby API Key`：仅用于查询媒体项对应的 STRM 路径；外部客户端仍由 Emby 正常鉴权。
- `Emby STRM 媒体库路径`：填写 Emby 容器中看到的路径，一行一个，例如 `/media/tencentdoc115`。
- `Emby → MoviePilot 路径映射`：两边容器路径不同时填写，例如 `/media/tencentdoc115|/data/tencentdoc115`。

MoviePilot 容器必须额外映射 `-p 8097:8097`，内网穿透或公网反向代理也必须指向 `8097`。Infuse、Emby App 和浏览器中的服务器地址应改为网关地址，不能继续连接 Emby 的 `8096`，否则请求不会经过插件。客户端要求转码时无法返回115直链，因此受管 STRM 只支持直接播放/直接串流；ISO 是否能被特定客户端识别取决于客户端本身。

115 临时直链按资源、文件和播放器 User-Agent 缓存在内存中，默认100分钟、最多4096条，插件重启即清空。网关只负责签发307，不代理视频正文；客户端后续直接连接115。

代理普通 Emby 响应时，网关不再照搬上游 `Content-Length`，并将播放器拖动、切换或退出造成的连接中断视为正常结束；未预料异常统一记录后返回502，避免 aiohttp 裸露500页面。

参考 go-emby2openlist 的做法，远程 STRM 返回 PlaybackInfo 或第一次命中播放入口时，网关会在后台请求一次 Emby 的 `PlaybackInfo` 并设置 `IsPlayback=true`、`AutoOpenLiveStream=true`，通知 Emby 打开远程媒体。相同媒体项和 MediaSourceId 在10分钟内只触发一次；失败会解除限制供下次重试，任务在网关停止时会被取消，不会无限积累。这个过程可能由 NAS 从115读取少量媒体头部，但实际播放数据仍由客户端从115直链读取。

PlaybackInfo 请求已通过 Emby 认证后，网关会按客户端 IP、User-Agent、媒体项和媒体源保存最多 10 分钟的短期路径关联；缓存最多 2048 条且插件重启或清空时立即释放。这样 Infuse 后续未重复携带 Token 的 Stream 请求仍能安全命中对应 STRM，而其它设备不能复用该关联。

## MoviePilot 原生检索和下载

- 原生检索搜索的是已经同步到插件 SQLite 的目录记录，而不是每次重新读取腾讯文档。默认开启“只检索已生成 STRM 资源”，因此搜索结果与已经构建好的 STRM 库一致。
- 搜索结果携带的是插件内部资源标记。MoviePilot 点击下载后，插件会截获该标记；不会把伪磁力交给 qBittorrent，也不会把 302 地址当种子。
- 电影分享包含多个视频时，当前按文件体积选择最大的主视频。电视剧下载使用构建 STRM 时已经保存的剧集文件列表；MoviePilot 传入选集范围时只下载对应集，否则下载该资源全部已识别剧集。
- 实际下载流程为“匿名取得文件列表（如有需要）→ 使用账户 Cookie 生成临时直链 → 插件流式下载到 MoviePilot 下载目录”。下载完成后可由 MoviePilot 下载器监控目录继续整理。
- 这条下载链路使用的是临时直链，但由插件自己跟踪进度、刷新过期链接和断点续传。直接向 qBittorrent 交付一个 HTTP 302 地址无法可靠进入 MoviePilot 的下载与整理生命周期，所以没有采用该方式。

## Unraid 与 Emby 路径示例

如果 MoviePilot 已有宿主机 `/mnt/user/data` 到容器 `/data` 的映射，可直接这样配置：

- 插件“STRM/元数据输出目录”：`/data/tencentdoc115`
- 宿主机实际目录：`/mnt/user/data/tencentdoc115`
- 插件“Emby 可访问的 MoviePilot 地址”：`http://UNRAID局域网IP:MoviePilot映射端口`，不能使用 `127.0.0.1`
- 插件“内置 Emby 直链网关端口”：`8097`
- 插件“Emby 内部地址”：`http://UNRAID局域网IP:8096`

在 Emby 容器中新增一条只读路径映射：

| Emby 宿主机路径 | Emby 容器路径 | 权限 |
| --- | --- | --- |
| `/mnt/user/data/tencentdoc115` | `/media/tencentdoc115` | Read Only |

然后在 Emby 中建立媒体库：电影库可加入 `/media/tencentdoc115/电影合集`、`/media/tencentdoc115/星火` 和 `/media/tencentdoc115/蚂蚁`；电视剧库加入 `/media/tencentdoc115/剧集` 和 `/media/tencentdoc115/星火-剧集`。如果在插件中使用了自定义分组名称，则把基础目录加入电影库，把对应的“分组名-剧集”目录加入电视剧库。

由于示例中 Emby 看到的路径是 `/media/tencentdoc115`，MoviePilot 看到的是 `/data/tencentdoc115`，直链网关的路径映射填写：

```text
/media/tencentdoc115|/data/tencentdoc115
```

把 MoviePilot Docker 命令增加 `-p 8097:8097`，然后把 Infuse 和内网穿透目标改为 `UNRAID地址:8097`。确认播放请求返回307后，可以停止对公网暴露 Emby 原始 `8096` 端口。
